### 1.1 回应 E1：巩固切片与反射响应谁抢谁

**先纠一个前提，再交原语。**

**反驳（前提）**："共享执行核"不成立——三时钟域的第一个卖点恰恰是**不共享**。R0 是独立时钟域独立线程（E4方案 §3.1），反射响应与巩固切片不存在对同一执行核的竞争；竞争只发生在 R2 内部（离线巩固 vs 归因复核 vs 观测作业共抢 R2 拍）。所以"什么信号允许它抢占反射弧"的答案是：**没有这个信号，这条优先级倒置在架构上不存在**。R0 不依赖 R1/R2 的任何输出（核心不变量），巩固开到一半，反射照常。E1 的问题问反了方向：不是巩固抢反射，是 R2 内部谁抢谁。

**接受（原语，三件套）** [未实测]：

1. **维护窗口原语**：巩固 = R2 上的"维护窗口"作业（窗口仲裁器排程，见 §5 底座行）。窗口内 R2 独占、R1 照常探测与行为、R0 永不受扰。生物对应不硬凑 unihemispheric sleep——那是"巩固期间行为必须不中断"的方案（海豚/鸟解）；本阶段做的是 NREM 式：皮层环离线、脑干-脊髓环在线。若 E1 坚持"巩固期间行为完全不间断"，才需要 R2 分片巩固的 unihemispheric 版，加价另议。这同时回答 E1 §6-5 的悬置（"嵌入式对应物是否存在由 E4 质询"）：存在，且其可失败判据并入我的 D2（杀 R2 演练天然覆盖"窗口中途死"）。
2. **觉醒中断的两条腿**："NE 突变 ⇒ 立即中断离线相"（E1 §3.4 原文）的传播路径 = NE 标志进广播包 → 离线循环**每片切片开头**检查标志；中断延迟 ≤ 1 个切片 WCET（预注册上限）。**兜底看门狗不在 R2**——R2 死了就没人中断自己（自喂狗结构，E4方案 病 6 已给同构判定：自己喂自己的狗测不到真死亡）：R0 挂纯标量墙钟计时器"离线窗口时长上限"，到点强制收窗。**为此 E1 必须出数**：R_r 的墙钟上限（"时长 R_r ∝ S"给的是比例不是上限）——没有这个数我看门狗无法预注册，这是落位表 E1 的必填格。

### 1.2 回应 E2：社会时差窗口在亚毫秒世界有没有存身之处

E2 原文（E2 §7）："δ 过小则被归入完美应答（=身体自我），过大则被归入零应答（=风）。请说明你的实时预算里给这个'社会时差窗口'留了多少，以及 MBP 心跳超时 3+1 拍的挂起机制能否承载'他者在场/缺席'的物理语义——还是说社会时间在你的亚毫秒世界里根本没有存身之处？"

**接受一半（心跳），反驳一半（存身之处），交出一个结构性让步（见 §3.3）。**

- **心跳承载不了在场/缺席——接受**。心跳的语义是"进程活着"，在场性的语义是"κ 通路近期在应答"。still-face 范式恰好是两层分离的实证设计：石头脸照顾者心跳完全健康、κ=0（E2 §3.2 原文"still-face：κ→0 但 C_own 照常"）。所以 D3 的三个 episode 条件在我这里操作化为**三个独立开关**：κ 置零 = still-face（进程活、应答死）；杀照顾者进程 = 真缺席；换设备实例 = 陌生人。E2 的 shams 是我 kill 矩阵的免费行——请 E2 确认这组操作化不破坏 D3 判据语义。INT §0 的"挂起 t=903 = 心跳超时 3+1 拍"只证明现有心跳测标志位存活（E4方案 病 6），它本来就不该被指望承载社会语义。
- **存身之处——有，但不在 R0，在世界时钟域**。照顾者按 E2 §3.2 的形状（"SENSE_C(t) = 自主节律动力 C_own(t) + κ·f_应答(CMD(t−δ)) + ξ"）注册为世界域设备：CMD 进照顾者自己的输入队列、在它自己的下一拍生效 ⇒ δ 不是碰巧出现的延迟，是**已知、可控、可预注册的 τ_dl**（与 E4方案 §4 对 world 的同款改造）。预算档位 [未实测，语义待 E2 出数]：δ ∈ {40, 100, 200} ms（2/5/10 个 R1 拍）为起点档。E2 原文说"尺度与实现归 E4/E3"——实现归我，但**哪个档能过 D2 的判据语义必须 E2 出数**；我只担保"δ 可设、可测、偏差可登记"。
- **约束反提**：δ 的稳定性比数值更重要——D2 吃的是应答结构的可学性，δ 抖动跨档则完美/高而不全应答的边界糊掉。我担保 τ_dl 方差上限（队列结构的自然性质），请 E2 在 D2 预注册 δ 容差。

### 1.3 回应 E3：最坏路径放哪 + 丢帧语义

E3 原文（E3 §7）："闭环里最坏路径 = 1 次 D=1024 矩阵向量 + |A|+1 次 cleanup + C=5 次弛豫 ≈ 2×10⁶ flops/步。你的 1kHz 预算下这一步放执行层还是放后台？世界包丢了拍，3) 预测步允许用 H_{t-1} 代替 H_t 吗——给出你的丢帧语义，我好写进判据。"

**先纠预算误读，再交落位与丢帧语义。**

- **1 kHz 是误读**：我的预算里 1 ms 只属于 R0（安全钳制，纯标量）；感知-预测-行动闭环属于 R1（50 Hz、≤8 ms/拍）；慢弛豫与巩固属于 R2（E4方案 §3.1 表）。E3 的闭环不是 1 kHz 问题，是 R1/R2 分配问题。

- **丢帧语义（点名交付，可直接写进判据）** [未实测]：
  1. 允许 H_{t-1} 代 H_t：世界包丢一拍，预测照做、行动照选；
  2. 该拍行动降权：包龄期超限 ⇒ G(a) 判定置信降级，回退上一拍 a* 或安全默认动作（门控参数决定）；
  3. **stale 写保护**：连续 ≥3 拍缺新包 ⇒ 惊讶门控写入（E3 §3.2 step 5 "M ← λ_M·M + η(e_t)·x_t ⊗ (a_{t-1} ⊛ H_{t-1})"）冻结，期间 e_t 只进日志不进 M——在 stale 键上写关联记忆是毒数据，比丢帧贵一个量级；恢复供包后解冻；

### 1.4 回应 E5：龄期语义与闭环调节是毒药关系

E5 原文（E5 §7）："若 R1 按'龄期>5s 回退默认'处理 β 包，调节器会看到自己的输出被吞（积分 windup，经典失控）……需要一个'慢控制变量跨环一致性'原语（如参数包带'调节中'标志：到期只降置信、不回退；仅当写者心跳死才回退）。"

**接受指控，认领漏洞，把原语补成完整版。**

- E5 说得对：E4方案 §3.3 的"R2 死了或超龄 ⇒ R1 用内置默认门控继续"只考虑了"参数过期"，没考虑"参数正被调节"——对正在被主动调节的控制变量，龄期回退 = 写者输出被吞 = windup。这是我的设计漏洞，认领。
- **采纳并加固**（完整原语 [未实测]）——参数包追加 `调节中` 标志 + 两条背压件：

  ```
  三态龄期语义：
    新鲜（龄期 ≤ 上限）      ⇒ 正常消费；
    调节中 且 过龄            ⇒ 只降置信、不回退（旧值继续用）；
    写者心跳死（≠ 过龄！）    ⇒ 才回退默认门控。
  背压件一：消费确认 ack（R1 → R2）——调节器知道包被消费；
            长期无 ack = 消费侧死，写者自行降速或挂起（防单侧狂奔）。
  背压件二：钳制通知（R0 → R2）——R0 把 β 钳进安全包络时通知写者，
            I_c 积分器冻结（anti-windup）。
  ```

  加固理由：E5 的原语只堵了"龄期回退吞输出"一条路；**钳制吞输出**是第二条通向 windup 的路（R0 的包络钳制在我方案里是硬的，β 撞包络是常态事件不是异常事件）——两条都堵，windup 才真的无处发生。
- **K3+K4 联立：签署**。E5 预备回应（E5 §7）："判据归我，接口归你，联合预注册"——接受，具体化：① 我的 D2 kill 矩阵每场演练打标记（时间戳+层身份+类型，定时包字段够用）；② E5 的 K-BATTERY 过滤带演练标记的窗口；③ 演练后我预注册"恢复期无新干预"静默窗（时长按 E5 的 T_rec 反推）；④ E5 K3 的"把 β_slow 强推离带"干预直接并入我的演练排程——同一场实验喂 D2+K3 两组判据，D 盘 10.7 GB 只付一次学费。
- **保留一处措辞分歧**：E5 说这是"恰好由消灭非平稳的架构制造"的新非平稳源——准确说法：三钟域消灭的是**单时钟伪共享**的非平稳（INT G1：bus.t 每拍 +2 是实证）；跨环调节引入的竞态是**新的、可命名的、有原语对策的**非平稳源。命名它、钳住它，不等于架构错了（详见 §4.4）。
